# Topology Visualiser Design

**Date:** 2026-04-25
**Status:** Approved

## Overview

Load a SCION project folder (structured like the reference `scion/` directory) and a `.topo` config file. The app runs `./scion.sh topology -c <topofile>` to generate the `gen/` directory, then reads the per-AS `topology.json` files from `gen/` to reconstruct the full network topology. The result is displayed as an interactive React Flow graph. Clicking any node or edge opens a Mantine Drawer on the right with details.

## Workflow

1. User clicks "Open Project" → native folder picker (selects the project root, e.g. `scion/`)
2. User selects a `.topo` file (file picker, filtered to `*.topo`)
3. Rust runs `./scion.sh topology -c <topo_file>` in the project folder (always re-runs; cleans and regenerates `gen/`)
4. Rust reads all `gen/AS*/topology.json` files and combines them into a `Topology`
5. Frontend transforms `Topology` → React Flow nodes + edges, lays out with Dagre, renders

## Data Model

### `IsdAsnDef` wrapper

`IsdAsn` from `scion-proto` has no `specta::Type` impl. A newtype wrapper bridges the gap:

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash, Serialize, Deserialize)]
#[serde(transparent)]
pub struct IsdAsnDef(pub IsdAsn);

impl specta::Type for IsdAsnDef {
    fn inline(_: &mut specta::TypeMap, _: specta::Generics) -> specta::DataType {
        specta::DataType::Primitive(specta::datatype::PrimitiveType::String)
    }
}
```

Serialises/deserialises as `IsdAsn` (string `"1-ff00:0:110"`). Specta emits `string` in TypeScript.

### Tauri-facing structs (derive `specta::Type, Serialize, Deserialize`)

```
Topology
  ases: HashMap<IsdAsnDef, AsInfo>
  links: Vec<Link>

AsInfo
  core: bool
  mtu: Option<u32>

Link
  a: LinkEndpoint
  b: LinkEndpoint
  link_type: LinkType          // Core | Child | Peer

LinkEndpoint
  as_id: IsdAsnDef
  router_name: String          // "br1-ff00_0_110-1"
  interface_id: u32            // e.g. 22076
  underlay_local: String       // "127.0.0.4:50000"
  underlay_remote: String      // "127.0.0.5:50000"

LinkType (enum)
  Core | Child | Peer
```

### TypeScript (generated by specta into `src/bindings.ts`)

`IsdAsnDef` → `string`. All other structs generated verbatim.

## Rust Backend

### Files

**`src-tauri/src/topology/mod.rs`**

Defines `IsdAsnDef`, `Topology`, `AsInfo`, `Link`, `LinkEndpoint`, `LinkType`.

Defines `RawAsTopology` matching the `gen/AS*/topology.json` schema:
```
RawAsTopology
  isd_as: IsdAsnDef
  attributes: Vec<String>            // [] or ["core"]
  mtu: Option<u32>
  border_routers: HashMap<String, RawBorderRouter>

RawBorderRouter
  interfaces: HashMap<String, RawInterface>   // key = interface_id as string

RawInterface
  isd_as: IsdAsnDef                  // remote AS
  link_to: String                    // "core" | "child" | "parent" | "peer"
  mtu: Option<u32>
  underlay: RawUnderlay
  remote_interface_id: Option<u32>   // present on peer links only

RawUnderlay
  local: String
  remote: String
```

`build_topology(raw: Vec<RawAsTopology>) -> Topology`:
1. Build `ases` map from all `isd_as` + `attributes`
2. Build an interface index: `HashMap<(IsdAsnDef, u32), (String, RawInterface)>` — key = `(as_id, interface_id)`, value = `(router_name, interface)`
3. For each interface, emit a link only if `local_as_id.0 < remote_as_id.0` (deduplication by IsdAsn u64 value)
4. Look up the remote endpoint from the interface index using the remote AS's topology data; for peer links `remote_interface_id` is available directly, for core/child/parent links find the remote interface by scanning for one pointing back to `local_as_id`
5. Normalise `link_to`: `"core"` → `Core`, `"child" | "parent"` → `Child`, `"peer"` → `Peer`

**`src-tauri/src/lib.rs`** — new Tauri command:

```rust
#[tauri::command]
#[specta::specta]
fn load_project(folder: String, topo_file: String) -> Result<Topology, String>
```

1. Run `./scion.sh topology -c <topo_file>` via `std::process::Command` in `folder` as working dir; capture stderr, return error if exit code non-zero
2. Glob `gen/AS*/topology.json`, read and deserialise each with `serde_json`
3. Call `build_topology`, return result

Registered in `collect_commands![]` and the `tauri-specta` builder.

## Frontend

### Components

```
AppShell.Main
  TopologyView
    OpenProjectButton     shown when no topology loaded
    ReactFlow
      IsdNode             (type: "isd")     large rectangle, label "ISD 1"
        AsNode            (type: "as")      rectangle, parent = ISD, label = AS hex
          RouterNode      (type: "router")  circle on AS border, label = interface_id
    Drawer                anchored right, shown on node/edge click
```

### Data flow

1. User clicks "Open Project" → `@tauri-apps/plugin-dialog` `open({ directory: true })` → folder path
2. User selects `.topo` file → `open({ filters: [{ name: "Topology", extensions: ["topo"] }] })` → topo path
3. `invoke("load_project", { folder, topoFile })` → receives `Topology`
4. `buildGraph(topology: Topology)` (`src/lib/topology.ts`) — pure function:
   - One ISD node per unique ISD number (from `as_id.split('-')[0]`)
   - One AS node per entry in `topology.ases`, parented to its ISD node
   - One router node per unique `(as_id, router_name)` pair appearing in links, parented to its AS node
   - Edges connect router node to router node
5. `layoutGraph(nodes, edges)` (`src/lib/layout.ts`) — pure function:
   - Run Dagre (`rankdir: "TB"`) per ISD using `Child` links to define rank hierarchy
   - Position ISD nodes side-by-side horizontally with padding
   - Router nodes positioned on the border of their parent AS node
6. React Flow renders the result

`buildGraph` and `layoutGraph` are pure functions with no React dependencies.

### Edge styles

| `link_type` | Style |
|---|---|
| `Core` | thick solid line |
| `Child` | thin solid line |
| `Peer` | dashed line |

### Details Drawer

Mantine `Drawer` anchored right, `size="md"`. `selectedElement` state in `TopologyView` set on node/edge click.

| Click target | Fields shown |
|---|---|
| ISD node | ISD number, member AS list |
| AS node | Full ISD-AS ID, core flag, mtu |
| Router node | Router name, interface ID, parent AS, underlay local/remote |
| Edge | Link type, endpoint A (AS + router + interface), endpoint B, mtu |

## Out of Scope

- Parsing `.topo` files directly (delegated to `scion.sh`)
- Loading pre-existing `gen/` without re-running `scion.sh`
- Saving or editing topologies
- Path visualisation (separate feature)
- Persisted layout (positions reset on reload)
- Tooltips on collapsed router nodes
