# Topology Visualiser Design

**Date:** 2026-04-25
**Status:** Approved

## Overview

Load a SCION `.topo` file via a native file picker, parse it in Rust, and display the network as an interactive graph in React Flow. ASes are nested inside ISD nodes; border router circles appear on AS borders when the topology file specifies interface IDs. Clicking any node or edge opens a Mantine Drawer on the right with details.

## Data Model

### Rust (internal)

`IsdAsn` from `scion-proto` is used throughout parsing for validation and to access `.isd()` / `.asn()`. A newtype wrapper exposes it through the Tauri boundary:

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash, Serialize, Deserialize)]
#[serde(transparent)]
pub struct IsdAsnDef(pub IsdAsn);

impl specta::Type for IsdAsnDef {
    fn inline(_: &mut specta::TypeMap, _: specta::Generics) -> specta::DataType {
        specta::DataType::Primitive(specta::datatype::PrimitiveType::String)
    }
}
```

`#[serde(transparent)]` means it serialises/deserialises as `IsdAsn` does (string `"1-ff00:0:110"`). Specta emits `string` in TypeScript.

### Tauri-facing structs (derive `specta::Type, Serialize, Deserialize`)

```
Topology
  ases: HashMap<IsdAsnDef, AsConfig>
  links: Vec<Link>

AsConfig
  core: bool
  voting: bool
  authoritative: bool
  issuing: bool
  cert_issuer: Option<IsdAsnDef>
  mtu: Option<u32>
  underlay: Option<String>

Link
  a: LinkEndpoint
  b: LinkEndpoint
  link_a_to_b: LinkType          // Core | Child | Peer

LinkEndpoint
  as_id: IsdAsnDef
  router_id: Option<String>      // "A", "B", etc. — absent in wide.topo-style files
  interface_id: Option<u32>      // absent in wide.topo-style files

LinkType (enum)
  Core | Child | Peer
```

### TypeScript (generated by specta into `src/bindings.ts`)

`IsdAsnDef` → `string`. `Topology`, `AsConfig`, `Link`, `LinkEndpoint`, `LinkType` are generated verbatim.

## Rust Backend

### Files

**`src-tauri/src/topology/mod.rs`**
- Defines `IsdAsnDef`, `Topology`, `AsConfig`, `Link`, `LinkEndpoint`, `LinkType`
- Defines internal `RawTopology` / `RawLink` structs that deserialise the YAML directly (keys and link endpoint strings are raw strings)
- `impl TryFrom<RawTopology> for Topology` — validates and converts: parses AS keys via `IsdAsn::from_str`, parses link endpoint strings via `parse_link_endpoint`
- `parse_link_endpoint(s: &str) -> Result<LinkEndpoint, _>`:
  1. Split on `#` → interface_id
  2. If remainder ends with `-<single uppercase letter>` → extract router_id, strip suffix
  3. Parse remainder as `IsdAsn`

**`src-tauri/src/lib.rs`**
```rust
#[tauri::command]
#[specta::specta]
fn load_topology(path: String) -> Result<Topology, String>
```
Reads file, calls `serde_yaml_ng::from_str::<RawTopology>`, converts via `TryFrom`, returns result. Registered in `collect_commands![]` and the `tauri-specta` builder.

### New Cargo dependencies
- `serde_yaml_ng` — YAML parsing (used by `scion-proto` serde tests; supports `IsdAsn` round-trips correctly)
- `tauri-plugin-dialog` — native file picker

## Frontend

### Components

```
AppShell.Main
  TopologyView
    OpenButton          shown when no topology loaded
    ReactFlow
      IsdNode           (type: "isd")     large rectangle, label "ISD 1"
        AsNode          (type: "as")      rectangle, parent = ISD, label = AS hex
          RouterNode    (type: "router")  circle, parent = AS, label = interface_id
    Drawer              anchored right, shown on node/edge click
```

### Data flow

1. User clicks "Open Topology" → `@tauri-apps/plugin-dialog` `open()` filtered to `*.topo`
2. Path passed to `invoke("load_topology", { path })` → receives `Topology`
3. `buildGraph(topology: Topology)` (`src/lib/topology.ts`) — pure function:
   - One ISD node per unique ISD number (from `as_id.split('-')[0]`)
   - One AS node per entry in `topology.ases`, parented to its ISD node
   - One router node per link endpoint where `interface_id` is present, parented to its AS node. Identity key: `(as_id, router_id)` when `router_id` is Some (all interfaces of the same named router share one node); `(as_id, interface_id)` when `router_id` is None (each bare interface gets its own node)
   - Edges: if both endpoints have `interface_id` → router-to-router; otherwise → AS-to-AS
4. `layoutGraph(nodes, edges)` (`src/lib/layout.ts`) — pure function:
   - Run Dagre (`rankdir: "TB"`) per ISD using CHILD links to define rank hierarchy
   - Position ISD nodes side-by-side horizontally with padding
   - Router nodes positioned on the border of their parent AS node
5. React Flow renders the result

`buildGraph` and `layoutGraph` are pure functions with no React dependencies, making them straightforward to test.

### Edge styles

| `link_a_to_b` | Style |
|---|---|
| `Core` | thick solid line |
| `Child` | thin solid line |
| `Peer` | dashed line |

### Details Drawer

Mantine `Drawer` anchored right, `size="md"`. `selectedElement` state in `TopologyView` set on node/edge click.

| Click target | Fields shown |
|---|---|
| ISD node | ISD number, member AS list |
| AS node | Full ISD-AS, core/voting/authoritative/issuing, cert_issuer, mtu, underlay |
| Router node | Router ID, interface ID, parent AS |
| Edge | Link type, endpoint A, endpoint B, mtu, bw, underlay |

## Link Endpoint Rules

`.topo` files vary in specificity:

- **Interface IDs present** (tiny.topo, default.topo): border router circles rendered; edges connect circle-to-circle
- **No interface IDs** (wide.topo): no border router circles for those links; edges connect AS-to-AS directly

The visualiser represents exactly what the `.topo` file contains — no border routers are synthesised.

## Out of Scope

- Loading `topology.json` (generated per-AS format) — only `.topo` files
- Saving or editing topologies
- Path visualisation (separate feature)
- Persisted layout (positions reset on reload)
- Tooltips on collapsed router nodes
